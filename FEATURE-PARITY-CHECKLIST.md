It is a source review, not a claim that every original test or interaction has been reproduced. All live/backend/native integration remains unverified.

## Required integration prerequisites

- Native passkeys need a platform bridge plus verified app IDs, signing/domain association and server origin compatibility. Native/web push and OS app links need a separately authorized integration phase.
- Durable native drafts require reviewed account-bound encrypted storage/key destruction/backup behavior. Native queue remains memory-only; no plaintext database or custom cryptography was substituted.
- Cooperating same-origin Universal tabs coordinate auth and send with Web Locks and pre-send `/me`. Another client/origin can still change the shared session between that check and POST. **Server-side expected-principal binding on the mutation is a prerequisite for closing that race across all clients.** No backend change was made.
- Native cookies/CSRF/WebSockets/media/permissions, frame pixel output, keyboard/safe areas and actual export receivers must be validated by the user on manual native builds. Source/mocks do not establish these properties.

## Intentional bounded choices versus unfinished parity

Explicit export confirmation, safe URL restrictions, native size limits, conservative lifecycle cancellation, PNG editing, dedicated temporary caches and absence of insecure native persistence are deliberate choices for this source pass. Simplified contact/poll/media details, global notification presentation and missing gesture shortcuts are unfinished parity, not claimed equivalents. Nothing here certifies production readiness.
